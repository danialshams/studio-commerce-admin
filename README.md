# Studio Commerce Admin — پنل مدیریت فارسی Next.js

پنل مدیریت **مستقل، RTL، موبایل‌اول** برای تحویل به صاحبان فروشگاه و سایت شرکتی. یک کدپایه، یک مدیر اصلی، سه قالب فروشگاهی یا قالب سفارشی. **هیچ وردپرس یا پنل مرکزی فروشنده در معماری وجود ندارد.**

## امکانات پیاده‌سازی‌شده

- **محصولات:** فهرست، جست‌وجو، مشاهده، ایجاد، ویرایش، آرشیو (حفظ سوابق سفارش)، قیمت تومان، قیمت قبل تخفیف، دسته‌بندی، SKU، تصویر شاخص، گالری، ویژگی‌های اختیاری، تنوع رنگ/سایز و موجودی؛ ثبت تغییرات موجودی.
- **سفارش‌ها:** فهرست، وضعیت‌های مجاز سفارش، کد رهگیری، یادداشت، اقلام و پرداخت‌ها، جزئیات چاپی. ایجاد سفارش و اعتبارسنجی پرداخت از سمت فروشگاه آینده انجام می‌شود، نه با داده ساختگی در پنل.
- **مشتریان، دسته‌بندی‌ها، کدهای تخفیف، روش‌های حمل، تراکنش‌ها (فقط مشاهده)، تأیید/رد دیدگاه‌ها.**
- **محتوا:** صفحه، مقاله، بنر، سئو، سکشن‌های صفحه اصلی، قالب انتخابی ۱/۲/۳/اختصاصی.
- **سایت شرکتی:** خدمات، پروژه‌ها و درخواست‌های مشاوره، با همان رابط پنل ولی منوی متناسب با نوع سایت.
- **داشبورد واقعی:** تعداد سفارش‌های در جریان، فروش پرداخت‌شده ثبت‌شده، مشتری‌ها، محصولات فعال، موجودی کم و آخرین سفارش‌ها؛ بدون آمار جعلی.
- **مدیر واحد:** ورود ایمیلی با scrypt، نشست httpOnly در PostgreSQL، محدودسازی تلاش ورود، محافظت مبدا POST/PATCH/DELETE و ثبت AuditLog. مدیر جدید/سطح دسترسی/ثبت‌نام آزاد وجود ندارد.
- **موبایل/تبلت:** طراحی RTL، ناوبری پایین در موبایل، منوی کشویی، جدول‌های کارت‌شده، فرم بزرگ کشویی، دکمه‌های قابل لمس و حالت Reduced Motion.
- قیمت‌ها همواره **عدد صحیح تومان** هستند؛ انتخاب واحد پول حذف شده است.

## پشته فنی

Next.js 16.4.3 (App Router)، React 19، TypeScript، CSS اختصاصی الهام‌گرفته از الگوهای سبک shadcn/ui، Lucide، Prisma 6 و PostgreSQL. تصاویر در S3-compatible object storage ذخیره می‌شوند (اختیاری تا اتصال حساب واقعی).

### راه‌اندازی

```bash
cp .env.example .env
# DATABASE_URL و ADMIN_EMAIL و ADMIN_PASSWORD را در .env تنظیم کنید.
npm install
npx prisma generate
npx prisma db push
npm run admin:setup
npm run dev
```

به `http://localhost:3000/login` بروید؛ مدیر در اولین نصب با اسکریپت و رمز حداقل ۱۴ کاراکتر ساخته می‌شود. اجرای دوباره `npm run admin:setup` رمز همان مدیر را جایگزین می‌کند و نشست‌های قبلی را باطل می‌سازد.

برای دیتابیس توسعه:

```bash
docker compose up -d postgres
```

در نسخه عملیاتی، برای تغییر schema از migration نسخه‌بندی‌شده استفاده کنید؛ `db push` فقط برای راه‌اندازی اولیه نمونه توسعه است. فایل `.env` هر مشتری جداگانه است.

### آپلود تصاویر

متغیرهای S3_ENDPOINT، S3_REGION، S3_BUCKET، S3_ACCESS_KEY_ID، S3_SECRET_ACCESS_KEY و S3_PUBLIC_URL را تنظیم کنید. فرمت‌های JPEG/PNG/WebP تا ۵ مگابایت پذیرفته می‌شوند و نوع فایل از امضای محتوایی بررسی می‌شود. فضای فایل باید خصوصی باشد و فقط مسیر public asset/CDN که برای تصاویر تعریف کرده‌اید قابل مشاهده شود. بدون این تنظیم، **آپلود فعال نیست** و خطای راهنمایی‌شده نمایش داده می‌شود؛ لینک HTTPS برای تصاویر نیز پذیرفته می‌شود.

### اتصال سه قالب فروشگاهی

- هر قالب Next.js از API عمومی فقط-خواندنی `/api/store/catalog` برای محصولات **فعال** استفاده می‌کند.
- محصول/موجودی/مشتری/تنظیمات در یک دیتابیس متعلق به همان مشتری ذخیره می‌شوند. قالب تعویض شود، داده‌ها باقی می‌مانند.
- هر یک از طراحی‌های ۱/۲/۳ می‌تواند از `themeId` و `homeSections` استفاده کند.
- به هر مشتری استقرار و دیتابیس و ذخیره‌سازی مستقل بدهید؛ این محصول SaaS چندمستاجری و پنل مرکزی فروشنده نیست.

## هنوز به اتصال واقعی نیاز دارد

این مخزن **پنل و API مدیریت** است؛ فروشگاه عملیاتی کامل و آماده تراکنش واقعی نیست. موارد زیر بسته به سفارش مشتری باید متصل یا تکمیل شوند:

1. **فرانت‌اند فروشگاه، سبد خرید، ثبت سفارش و رزرو امن موجودی** به‌همراه تست همزمانی؛ هنوز موجود نیستند.
2. **درگاه پرداخت ایرانی** با callback امن و اعتبارسنجی سمت سرور، کنترل درخواست‌های تکراری، بازپرداخت واقعی و روش پرداخت در محل. صفحه تراکنش‌ها فقط تاریخچه داده معتبر را نمایش می‌دهد؛ دستی نمی‌توان وضعیت آن را به «پرداخت‌شده» تغییر داد.
3. **سرویس پیامک و ایمیل، صدور فاکتور رسمی، حمل‌ونقل واقعی و سیستم مرجوعی/بازپرداخت بانکی**؛ فعلاً فقط داده و بخش مدیریت برای بعضی از آن‌ها وجود دارد.
4. **مهاجرت پایگاه داده نسخه‌بندی‌شده، مانیتورینگ، پشتیبان‌گیری، آزمون نفوذ و تست end-to-end** قبل از دریافت اطلاعات واقعی مشتریان. ساخت اولیه schema در توسعه با Prisma db push امکان‌پذیر است.
5. **آپلود رسانه** پس از تنظیم مخزن S3 و CDN.

## تست

```bash
npm run test
npm run typecheck
npm run build
```

CI در GitHub پس از نصب بسته‌ها، یک PostgreSQL ایزوله ایجاد می‌کند و تست‌های ساختاری، typecheck و build را اجرا می‌کند. محیطی که آرشیو در آن ساخته شده دسترسی به registry npm نداشت؛ بنابراین `npm install` و **بیلد واقعی Next.js هنوز در آن اجرا/تأیید نشده است**. تست‌های Node.js محلی برای قواعد اصلی و صحت وجود فایل‌ها پاس شده‌اند؛ این معادل تأیید عملکرد همه صفحات نیست.

## مجوز و طراحی

ظاهر و CSS این پروژه از صفر نوشته شده و از الگوهای عمومی shadcn/ui الهام می‌گیرد؛ **هیچ فایل یا کدِ پنل آماده ثالث کپی نشده است**. قالب Kiranism (MIT) بررسی شد اما به‌خاطر Clerk Organizations/Billing و امکانات اضافی برای مدیر واحد، به‌صورت کامل استفاده نشد. برای تجاری‌سازی، مجوز dependencies را بررسی و یک نسخه قفل‌شده از dependencyها پس از اولین نصب ایجاد کنید.
